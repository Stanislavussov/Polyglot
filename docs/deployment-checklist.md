# Deployment Checklist

## Infrastructure

- Provision a VPS or container host with Docker Engine and Docker Compose.
- Create `/opt/polyglot` on the host and make it writable by the deploy user.
- Run `deploy/ansible/site.yml` or apply equivalent hardening: firewall, fail2ban, SSH key auth, no password login, no root SSH login.
- Open only required inbound ports: SSH, HTTP/HTTPS, admin panel, admin API, and metrics if they are intentionally public.
- Configure DNS for the bot/admin hostnames and terminate TLS in a reverse proxy before exposing admin traffic publicly.
- Configure a managed PostgreSQL database and store its connection string in `DATABASE_URL`. The production compose deployment does not run a PostgreSQL container.

## GitHub Secrets

- `DOCKER_USERNAME`: Docker registry username.
- `DOCKER_TOKEN`: Docker registry token with push/pull access.
- `VPS_HOST`: VPS hostname or IP.
- `VPS_USER`: SSH deploy user.
- `VPS_SSH_KEY`: private key for the deploy user.
- `BOT_TOKEN`: Telegram bot token.
- `DATABASE_URL`: production PostgreSQL connection string.
- `OPENROUTER_API_KEY`: OpenRouter API key.
- `JWT_SECRET`: long random secret for admin JWT signing.
- `ADMIN_PANEL_DOMAIN`: public admin panel hostname, for example `admin.example.com`.
- `ADMIN_API_DOMAIN`: public admin API hostname, for example `admin-api.example.com`.
- `REPOSITORY`: deployment metadata value if still required by downstream scripts.

## Runtime Variables

- `BOT_IMAGE_NAME`: bot image tag, generated by the deploy workflow.
- `MIGRATE_IMAGE_NAME`: migration image tag, generated by the deploy workflow.
- `ADMIN_API_IMAGE_NAME`: admin API image tag, generated by the deploy workflow.
- `ADMIN_IMAGE_NAME`: admin panel image tag, generated by the deploy workflow.
- `DATABASE_URL`: must be present; bot, migrations, and admin API startup fail without it.
- `JWT_SECRET`: must be present; admin API startup fails without it.
- `ADMIN_PANEL_URL`: generated by the deploy workflow from `ADMIN_PANEL_DOMAIN`; must match the browser origin allowed by CORS.
- `PUBLIC_API_URL`: generated by the deploy workflow from `ADMIN_API_DOMAIN`; must be reachable by admin users' browsers.
- `ADMIN_API_PORT`, `ADMIN_PORT`, and `METRICS_PORT`: set only when host port defaults need to change.
- The default AI model is managed in the admin app and stored in the database. The bot falls back to `openai/gpt-5-nano` only if DB settings are unavailable.

## First Deploy

- Push to `master` and confirm CI, image builds, VPS migration, and compose rollout complete.
- On the VPS, verify `docker compose ps` shows healthy `bot`, `admin-api`, and `admin`.
- Seed the first admin explicitly with `ADMIN_EMAIL` and `ADMIN_PASSWORD`; never rely on defaults.
- Log in to the admin panel, call `/api/auth/me` through the UI session, and verify dashboard stats load after authentication.
- Verify bot health at `/healthz`, admin API health at `/healthz`, and admin panel health through the reverse proxy.
- Rotate the seed admin password after first login and store credentials in the team password manager.
