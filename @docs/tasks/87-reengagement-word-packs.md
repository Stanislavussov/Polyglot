## Проблема

Пользователь, который не заходит 14+ дней (`INACTIVITY_DAYS`), раз в 5 дней
(`REENGAGEMENT_INTERVAL_DAYS`) получает одно слово: сначала из своего словаря, потом из
зашитого в код списка hook-слов (`getHookWords`). Это и есть сейчас «пресет».

- Словарь он уже бросил, поэтому слово оттуда — то, что его не удержало.
- Hook-слова лежат в коде: владелец не может положить туда свои находки, поменять их
  или выключить без релиза.
- Карточка возврата выглядит так же, как обычное ежедневное уведомление, и ничем не
  выделяется. А именно её человек должен открыть.

## Цель

Вернуть ушедшего пользователя одним интересным словом. Владелец сам собирает **наборы**
из сложных и любопытных слов (уровень C1+), публикует их из своего словаря в боте, и
каждый ушедший пользователь получает слово на **том языке, который он учит**, с
объяснением на родном.

Не цель: настройка у пользователя. Ушедший пользователь настройки не открывает, поэтому
механизм работает без его участия.

## Решения (согласованы 2026-11-06)

| # | Вопрос | Решение |
|---|---|---|
| 1 | Где создаются наборы | В боте: админ публикует свой словарь кнопкой. Управление — в админке |
| 2 | Кому и когда | Автоматически, в механизме возврата (lapsed sweep). Выбора у пользователя нет |
| 3 | Что со словом после показа | Карточка с кнопкой «💾 В словарь». Сохранённое слово идёт в SRS |

## Модель

**Набор** — список *понятий*. У понятия есть заголовок на каждом языке обучения: не
дословный перевод, а естественный эквивалент того же уровня. Немец получает немецкое
слово, испанец — испанское, а объяснение — на родном языке получателя.

```
word_packs
  id, slug (unique), emoji, title, title_i18n jsonb, is_active,
  source_dictionary_id → vocabulary_dictionaries (set null), created_by_user_id → users (set null),
  created_at, updated_at

word_pack_items
  id, pack_id → word_packs (cascade), sort_order, is_active,
  source_lang, source_headword,           -- как слово записано в словаре автора
  level ('B2'|'C1'|'C2'), emoji,
  headwords jsonb Record<lang, string>,   -- эквивалент на каждом языке; язык без эквивалента отсутствует
  created_at
  unique (pack_id, source_lang, source_headword)
```

Отрисованная карточка `(язык обучения, родной язык, headword)` кэшируется **в той же
таблице `onboarding_demo_cards`**, что и hook-слова: ключ тот же, путь «кэш → JIT-перевод»
в `preset-picker.ts` уже есть. Слова из набора пишутся в кэш с `is_active = true`: автор —
админ, и отдельное ревью не нужно. Выключить слово можно в админке.

## Поведение

### П1. Публикация набора (бот, только `audience_group = admin`)

1. В просмотре своего словаря (именованного, `vocabulary_dictionaries`) админ видит кнопку
   «📦 Сделать набором». Обычный пользователь её не видит, сервер проверяет роль при нажатии.
2. Нажатие запускает фоновую задачу и сразу отвечает «Собираю набор…».
3. Каждое слово словаря получает один вызов ИИ (пачками по 10). Модель:
   - определяет уровень CEFR. Слова ниже порога (по умолчанию **B2**, настраивается в
     админке) в набор не попадают;
   - на каждом из поддерживаемых языков даёт естественный эквивалент того же уровня и
     регистра. Если эквивалента нет, язык пропускается: лучше не прислать, чем прислать
     дословный перевод идиомы;
   - даёт эмодзи.
4. Итог приходит одним сообщением: «Набор „<имя словаря>“: 42 слова, 13 пропущено
   (слишком простые)». Повторное нажатие пересобирает набор: новые слова добавляются,
   ручные выключения в админке сохраняются.
5. Название и эмодзи берутся из словаря, переводы названия редактируются в админке.

### П2. Выбор слова для ушедшего пользователя

`pickLapsedWord`, по порядку:

1. **Слово из активного набора** на одном из языков обучения пользователя, которое ему
   ещё не отправляли (та же дедупликация по `notification_history`, что и сейчас). Наборы
   и слова перемешиваются детерминированно по `userId`, как в `presetCandidates`, чтобы
   вся когорта не получала одно и то же слово в один день.
2. Слово из его словаря, как сейчас.
3. Hook-слово, как сейчас.
4. Текст-приглашение, как сейчас.

Набор стоит выше словаря, потому что задача этой карточки — удивить, а не напомнить.
У активных пользователей с закончившимся словарём наборы встают между словарём и
hook-словами, порядок «словарь первым» для них не меняется.

### П3. Как выглядит карточка возврата

Задача карточки — чтобы её открыли, поэтому изначально она показывает меньше обычной:

```
🔥 <эмодзи набора> <название набора на языке интерфейса>

🇩🇪 <b>Fernweh</b>
Как думаете, что это значит?

[👁 Показать]  [💾 В словарь]
[⚙️]
```

- «👁 Показать» открывает обычную обратную сторону карточки, ту же, что в Task 86.
- «💾 В словарь» создаёт запись в словаре пользователя из отрисованной карточки
  (`source = { kind: "word_pack", packId }`). Дальше слово идёт по SRS как любое
  сохранённое.
- Любое нажатие — это интерактивность. `lastInteractionAt` обновляется, и пользователь
  выходит из режима возврата, как сейчас.

### П4. Админка

Страница «📦 Наборы слов»:
- список наборов с включением и выключением, названием (+ i18n) и эмодзи;
- слова набора: заголовки по языкам (можно править), уровень, выключение слова;
- порог уровня (system setting `wordPackMinLevel`);
- **статистика по набору**: отправлено, открыто, сохранено, вернулись в течение 48 ч.
  Источник — `notification_deliveries` и `notification_interactions`. По ней видно,
  какой набор возвращает людей.

## Метрики и события

- `notification.pack.picked` `{ packId, lang, origin: cache|jit }`

## Тесты (сначала спека → тесты)

Интеграционные (`*.integration.test.ts`, реальный диспетчер + Postgres):
- И1: админ нажимает «📦 Сделать набором» → в БД набор и слова, слова ниже порога
  отфильтрованы, язык без эквивалента отсутствует в `headwords`.
- И2: не-админ не видит кнопку, а прямой callback ничего не создаёт.
- И3: ушедший пользователь, учит `de` → получает немецкий заголовок из набора, а не слово
  своего словаря; второй прогон даёт другое слово.
- И4: «💾 В словарь» на карточке возврата → запись в словаре с SRS-строкой, повторное
  нажатие дубль не создаёт.
- И5: набор выключен в админке → ушедший пользователь получает слово из словаря или
  hook-слово, как раньше.

Юнит: порядок слоёв в `pickLapsedWord`, перемешивание наборов по `userId`, фильтр по
уровню, схема ответа локализатора.

## Срезы

1. Схема (`word_packs`, `word_pack_items`) + репозиторий + типы в core. `db:generate`.
2. Локализатор (ИИ-схема + сервис) + публикация в боте для админа. Тесты И1, И2.
3. Слой набора в `pickLapsedWord` и в пути «словарь закончился». Тесты И3, И5.

5. Админка: страница, API, статистика.

Оценка: L (2–3 дня), срезы 1–3 дают ценность сами по себе.

## Риски

- **Дословные эквиваленты.** Интересное слово часто не имеет пары. Защита — пропуск
  языка и правка заголовков в админке. Качество стоит проверить вручную на первом наборе.
- **Стоимость.** Публикация — ~1 вызов на слово. Отрисовка — JIT по требованию, один раз
  на пару (язык, родной язык), дальше из кэша.
- **Слишком часто.** Частоту не трогаем: по-прежнему одна карточка в 5 дней.
