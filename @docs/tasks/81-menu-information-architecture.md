## Проблема

Точки входа размазаны по трём несогласованным поверхностям, и ни одна из них не полная.

| Поверхность | Что показывает | Чего не хватает |
|---|---|---|
| Список команд Telegram (`/`) | 9 пунктов: start, translate, pick, dictionary, flashcard, videos, template, settings, report (+ changes для admin/tester) | плоский, без иерархии; `/mentor` и `/review` закомментированы в `getLocalizedCommands` |
| Reply-клавиатура | 4 кнопки: Подобрать слова / Словарь / Карточки / Видео | нет настроек, нет репорта, нет повторения, нет наставника |
| Текст `welcomeBack` | третий набор: translate / dictionary / settings | не совпадает ни с клавиатурой, ни со списком команд |

Конкретные дефекты:

1. **Мёртвые фичи.** `/review` (SRS) и `/mentor` зарегистрированы в `bot-factory.ts`, но
   скрыты из списка команд и отсутствуют на клавиатуре. Достучаться до них можно только
   набрав команду по памяти — то есть практически никак.
2. **`/translate` — шум.** Перевод это always-on режим по умолчанию (`mode-router.ts`
   падает в него даже из `idle`). Отдельная команда ничего не включает, но занимает
   строку в списке.
3. **`/template` и `/changes` — не верхний уровень.** Конструктор шаблона это настройка,
   а `/changes` вообще виден только admin/tester, но при этом сидит в общем списке.
4. **Одна плоскость на всё.** Ежедневное («перевести», «повторить») и разовое
   («сменить родной язык») лежат рядом с одинаковым весом.
5. **Меню настроек тоже плоское** — три отдельные кнопки языков подряд
   (`set:native`, `set:learning`, `set:interface`) там, где нужна одна группа «Языки».

## Целевая структура

### Reply-клавиатура — три горячие кнопки

```
┌────────────┬────────────┬───────────┐
│ 🎴 Карточки│ 🧑‍🏫 Ментор │ 📖 Словарь│
└────────────┴────────────┴───────────┘
```

Не меню, а именно горячие кнопки: это то, за чем учащийся тянется по нескольку раз за
сессию, и перед ними не должно быть ни одного лишнего экрана. Три в ряду — та плотность,
которую Telegram рисует одной строкой; бюджет подписи ~10 символов (es `Diccionario` = 11,
самый широкий, переносится, а не обрезается). Подписи взяты из отгруженных на `develop` —
они и были подобраны под эту ширину.

### `/menu` — всё остальное, отдельным сообщением

```
📋 Меню
  📖 Словарь        menu:dict
  🎓 Обучение       menu:learn
  ⚙️ Настройки      menu:settings
  🐛 Сообщить       menu:report
  ✕ Закрыть        menu:close
```

**Навигация правит одно сообщение, выдача контента присылает новое.** Граница проходит не
по «меню/подменю», а по «навигация/контент»:

| Действие | Как |
|---|---|
| `/menu`, первое открытие | новое сообщение — править нечего |
| Категория → подменю, «⬅️ Назад», выбор языка | правка на месте |
| Меню → карточки, повторение, видео, словарь, репорт | новое сообщение, меню удаляется |

Почему так, а не «каждое меню — новое сообщение»: стопка мёртвых меню хоронит карточки,
за которыми пользователь пришёл, а меню пятиминутной давности показывает прежний план и
прежний остаток кредитов — и тапают именно его, потому что оно ближе. Возражение про
48-часовой лимит редактирования уже закрыто в репозитории: `editMessageTextOrReply`
присылает тот же экран новым сообщением, когда правка невозможна.

### Хаб «🎓 Обучение» — callbacks `lrn:*`

| Кнопка | Callback | Обработчик (существует) |
|---|---|---|
| ✨ Подбор | `lrn:pick` | `handlePickWordsCommand` |
| 🎴 Карточки | `lrn:cards` | `handleFlashcardCommand` |
| 🔁 Повторение | `lrn:review` | `handleReviewCommand` ← **впервые доступен из UI** |
| 🎬 Видео | `lrn:videos` | `handleVideosCommand` |
| 🧑‍🏫 Ментор | `lrn:mentor` | `handleMentorCommand` |
| ⬅️ Назад | `menu:root` | возврат в меню правкой на месте |

Ментор дублируется горячей кнопкой намеренно: он и частый, и логически принадлежит
режимам обучения.

> **Мерж.** Ветка сделана до менторских коммитов `develop`, где `/mentor` и в списке
> команд, и под платным гейтом (`ensurePaidFeatureForMessage(ctx, FEATURE_KEYS.mentor)`).
> При мерже `apps/bot/src/scenes/mentor.scene.ts` разрешать **в пользу `develop`** — взять
> версию этой ветки значит молча снести гейт. Гейт и горячая кнопка совместимы (подписчик
> попадает в режим, free получает экран апгрейда; интеграционный тест поэтому арендует
> `plan: "pro"` и переживает мерж). Открытый продуктовый вопрос: заслуживает ли платный
> режим одного из трёх постоянных слотов на клавиатуре free-тарифа.

### Меню «⚙️ Настройки» — сгруппировано

```
🌐 Языки            → set:lang   ── подменю: родной / изучаемые / интерфейс
🔔 Уведомления      → set:notif  ── существующее подменю
📝 Шаблон перевода  → set:tpl    ── переезд /template
💳 Подписка         → set:plan
🆕 Что нового       → set:changes ── только admin/tester
✖️ Закрыть          → set:close
```

Подменю «🌐 Языки» переиспользует `set:native` / `set:learning` / `set:interface`; `set:back`
из пикера ведёт в группу, `set:root` — в корень.

### Список команд Telegram

```
🚀 /start       Запустить бота
☰ /menu        Меню: режимы обучения, настройки, сообщить
📖 /dictionary  Личный словарь
🎓 /learn       Режимы обучения
⚙️ /settings    Настройки
🐛 /report      Сообщить о проблеме
```

`/translate`, `/pick`, `/flashcard`, `/videos`, `/template`, `/review`, `/mentor`, `/changes`
**остаются зарегистрированными** — просто не публикуются через `setMyCommands`.

## Механика и риски

### 1. Старые лейблы на экране — реальный баг, а не мелочь ⚠️

`buildMainKeyboard` навсегда меняет набор кнопок, но reply-клавиатура живёт в клиенте
Telegram до тех пор, пока бот не пришлёт новую. Между деплоем и следующим сообщением
пользователя у него на экране висит **старая** раскладка: «✨ Подобрать слова» или сменившее
её «✨ Подбор», и «🎬 Видео». Если убрать их из индекса `getLabelIndex()`, тап уйдёт мимо
`bot.hears` в `modeRouterMiddleware`, и бот **переведёт слово «Подбор»** вместо запуска
пикера. Карточки, ментор и словарь в таблице не нужны: они остались живыми горячими
кнопками и индексируются как текущие.

Решение: `LEGACY_MENU_LABELS` — отдельная таблица «старый лейбл → действие», вливаемая в
тот же индекс. Плюс `logEvent("menu.legacy_tap")`, чтобы через месяц по метрике увидеть,
что алиасы можно выкинуть.

**Строки в таблице — литералы, а не `t()`-лукапы.** Первая реализация резолвила алиасы
через `t(labelKey, lang)` и была неправа: так таблица следует за *текущим* переводом, а не
за отгруженным. Ключи-то живые — `menuBtnFlashcards` подписывает кнопку хаба — и любой
переводчик, «улучшивший» его, молча снял бы с учёта алиас, всё ещё висящий у кого-то на
экране. То есть сломал бы ровно ту страховку, ради которой таблица заведена. Это
исторические артефакты, а не переводы; таблица уходит целиком в тот день, когда
`menu.legacy_tap` перестанет срабатывать.

Промежуточно я вернул было французское `Dictionnaire` вместо сокращённого `Mots` — под
раскладку в две кнопки, где бюджет вырос до ~15 символов. С возвратом к трём в ряду это
отменено: подписи выровнены байт-в-байт с отгруженными на `develop`, и `Mots` снова живая
подпись, а не алиас. Расхождение «подсказка зовёт искать одно, на кнопке другое» ловится
сверкой `mainMenuHint` с реальными подписями по всем 11 локалям.

### 2. `MAIN_KEYBOARD_VERSION` 3 → 4

Обязательно, иначе `mainKeyboardMiddleware` посчитает всех уже обслуженными и новая
клавиатура не доедет ни до кого. Версия лежит в Postgres-сессии, так что bump
переустанавливает клавиатуру ровно один раз на пользователя.

### 3. `oneTime()` остаётся

Не делать `persistent()`. Обоснование уже записано в `main-menu.ts` — закреплённая
клавиатура навсегда съедает низ экрана. Категории от этого не становятся менее
доступными: они за иконкой ⌨️ рядом с полем ввода, и `mainMenuHint` про это говорит.

### 4. Тексты, которые разъедутся, если их не тронуть

`mainMenuHint` и `welcomeBack` перечисляли третий, свой набор входов. Оба переписаны: они
называют три горячие кнопки и `/menu`, и сверка с реальными подписями прогоняется по всем
11 локалям.

### 5. Флаги ожидания ввода

Горячая кнопка доходит до режима мимо `modeRouterMiddleware` — а это единственное место,
где потребляются три флага «жду твоё следующее сообщение»: `awaitingNotifContext`,
`dictionaryWizard`, `awaitingTranslationClarificationContext`. Оставленные взведёнными, они
съедают следующее слово пользователя: оно уезжает в контекст уведомлений, или становится
именем нового словаря, или уточнением к предыдущей карточке. Тап по кнопке — явный отказ от
приглашения, поэтому все три сбрасываются в обработчике `bot.hears`.

### 6. Сломались существующие тесты

`word-picker.integration.test.ts` брал лейбл как «первая кнопка первого ряда» — переписан на
явный маршрут `/menu` → `menu:learn` → `lrn:pick`. Также правились `main-menu.test.ts`,
`commands.test.ts`, `start.test.ts`, `onboarding-flow.test.ts`, `settings.scene.test.ts`,
`main-keyboard.integration.test.ts`.

### 7. i18n — 11 локалей

Новые ключи: `menuBtnLearn`, `menuBtnSettings`, `menuBtnReport`, `cmdDescLearn`,
`learnHubTitle`, `settingsGroupLanguages`, `settingsGroupTemplate`, `settingsGroupPlan`,
`settingsGroupChanges`. Существующие `menuBtnPickWords` / `menuBtnFlashcards` /
`menuBtnVideos` **переиспользуются** внутри хаба — переводить заново нечего.

Файлы локалей: en, ru, cs, de, es, fr, it, kk, pl, pt, uk. `setBotCommands` рассылает
только по `LOCALES_WITH_FILES` (en/ru/cs) — этот список не трогаем.

## Как это собрано

1. **`utils/main-menu.ts`** — один ряд из трёх горячих кнопок, `MainMenuAction =
   flashcard|mentor|dictionary`, `LEGACY_MENU_LABELS` замороженными литералами,
   `MAIN_KEYBOARD_VERSION` 3 → 4.
2. **`scenes/menu.scene.ts`** (новый) — `/menu` и callbacks `menu:*`. Навигация через
   `editMessageTextOrReply`, выдача контента — через `handOff` (удалить меню, а если
   Telegram отказал по 48 часам — хотя бы снять кнопки).
3. **`scenes/learn.scene.ts`** (новый) — хаб `lrn:*`. Префикс `lrn:`, а не `learn:`:
   `LEGACY_ONBOARDING_CALLBACK_PATTERN` = `/^(?:lang|learn|level):/` регистрируется раньше
   и съел бы весь неймспейс. Кнопка «Назад» несёт литерал `menu:root`, чтобы не замкнуть
   цикл импортов с `menu.scene.ts`.
4. **Настройки** — `loadSettingsView` один на команду и на перерисовку. Раньше это были два
   тела, и одно считало кредиты за сутки против месячного лимита.
5. **`bot-factory.ts`** — `/menu`, `/learn`, `menu:*`, `lrn:*`, новые `set:*`; ветка
   `bot.hears` на три горячие кнопки и алиасы, со сбросом всех трёх флагов ожидания ввода.
6. **i18n** — 14 новых ключей в 11 локалях; `menuBtn*` выровнены байт-в-байт с `develop`.

## Спецификация тестов

### Unit
- раскладка ровно один ряд из трёх; `one_time_keyboard`, `is_persistent` не выставлен
- каждая горячая подпись ≤ 11 символов во всех 11 локалях
- **обе генерации подписи пикера** резолвятся, длинная и однословная
- `MAIN_KEYBOARD_VERSION` запинен значением: иначе раскладку можно поменять, забыв бампнуть,
  и ни один тест не упадёт, а пользователи останутся со старой клавиатурой
- список команд ровно `[start, menu, dictionary, learn, settings, report]`

### Integration — `menu-navigation.integration.test.ts`
Каждый ассерт пинит строку, уникальную для **одного** экрана. Пустые состояния словаря,
колоды и повторения все начинаются с «Your dictionary is empty», поэтому совпадение по
этому префиксу не доказывает ничего.

1. три горячие кнопки → колода / ментор (`plan: "pro"`, см. «Мерж») / словарь
2. `/menu` присылает новое сообщение с пятью callbacks
3. переходы `menu:learn` ↔ `menu:root` правят **то же** сообщение (`sentMessages == []`)
4. `lrn:review` → SRS, и явные негативы: колода и словарь **не** отвечали
5. `menu:dict` удаляет меню и открывает словарь
6. `menu:close` ничего не запускает
7. **legacy-подпись «✨ Pick» открывает пикер, а не переводится.** Отпечаток — callback
   `wp:p:` (тест сам заводит пресет, потому что база лейна общая) плюс негатив: подпись не
   вернулась эхом в тексте. Проверено мутацией: убираешь алиас — тест падает.
8. `set:lang` → `set:native` → `set:back` возвращает в группу, `set:root` — в корень
