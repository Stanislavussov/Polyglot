# T07 — RBAC + единый auth-хук (убрать 11 копий)

- **Приоритет:** P1 (High)
- **Фаза:** 1 — Безопасность
- **Оценка:** ~1.5 дня
- **Зависит от:** [T06](T06-admin-token-revocation.md) (единый хук — общая точка)
- **Блокирует:** [T27](T27-admin-service-layer-contracts.md)
- **Связано:** —
- **Находки:** S8

## Проблема

`apps/admin-api/src/plugins/auth.ts:19-30` — роль (`superadmin`) подписывается в JWT и кладётся в `request.adminUser`, но **ни один маршрут не проверяет `role`**: любой активный админ может удалять AI-модели, тарифы, менять планы пользователей. Декоратор `authenticate` из `plugins/auth.ts` — мёртвый код: каждый route-файл копипастит собственный `onRequest`-хук `jwtVerify` (11 повторов).

## Затронутые файлы

- `apps/admin-api/src/plugins/auth.ts:19-30`.
- Все 11 route-файлов в `apps/admin-api/src/routes/` с продублированным `onRequest`.

## Решение

1. Единый preHandler/hook на префиксе `/api`: `jwtVerify` + рантайм-проверка `isActive` (из [T06](T06-admin-token-revocation.md)) в одном месте; убрать 11 копий.
2. `requireRole("superadmin")` (или матрица прав) для деструктивных операций: удаление AI-моделей/тарифов, изменение планов.
3. Удалить мёртвый декоратор `authenticate` либо сделать его тем самым единым хуком.

## Критерии приёмки

- [ ] Деструктивные маршруты (удаление моделей/тарифов) требуют нужной роли; недостаточная роль → 403.
- [ ] `jwtVerify`/`isActive` заданы в одном месте, дублей в route-файлах нет.
- [ ] `knip`/`lint:knip` не показывает мёртвый `authenticate`.

## Тесты (spec-first)

- Integration-тест: админ без роли `superadmin` получает 403 на удалении AI-модели; с ролью — 200.
- Тест, что все маршруты по-прежнему требуют валидный JWT (регресс на общий хук).

## Примечания

Консолидация хука — фундамент для сервисного слоя [T27](T27-admin-service-layer-contracts.md).
