- **Приоритет:** P3 (Low — тех-долг, накопительно)
- **Фаза:** 3 — Архитектурные инвестиции

- **Зависит от:** —
- **Блокирует:** —
- **Связано:** [T21](T21-single-source-of-truth.md), [T22](T22-refactor-translate-helper-di.md)
- **Находки:** A5, A9, A10, A11, A15, A16, A17, A19, A20, A21

## Проблема

Набор архитектурных «заусенцев» в core/адаптерах, каждый по отдельности не критичен, но накопительно ухудшает расширяемость:

- **A5:** фантомная зависимость — core использует zod в рантайме в 7 файлах, не объявляя в `deps` (работает через walk-up на корневой package.json). То же в `@polyglot/adapter-ai`.
- **A9:** логика в index.ts вопреки Hard Rule #4 — реализация AI-адаптера (`adapters/ai/src/index.ts:34-215`) и rate-limit (`rate-limit/index.ts`) живут в index-файлах.
- **A10:** тройное дублирование ~60-строчного каркаса timeout→вызов→логирование в AI-адаптере (`index.ts:34-92,102-151,165-215`).
- **A11:** `GenerateObjectFn` объявлен трижды с разными сигнатурами; двойной DI-механизм; костыль TS2308 (`core/src/index.ts:79-89`).
- **A15:** промпт+схема «контекстного предложения» в notifications-адаптере; в промпт подставляются коды языков вместо названий («in ru»).
- **A16:** все deps `NotificationServiceDeps` опциональны — недособранный контейнер молча не шлёт уведомления.
- **A17:** синглтон AI-клиента, глобальные сеттеры-локаторы, чтение `process.env` внутри адаптера.
- **A19:** тип уведомления — закрытый union, продублированный в двух портах + switch в scheduler.
- **A20:** `I18nParams` не используется (`t()` берёт произвольный Record); `I18nKey` — ручной 315-строчный union без компайл-связки с en.json.
- **A21:** два механизма логирования; `SubscriptionPlan = string`; порт AI именует zod; «Telegram bot» в mentor-промпте; шим-баррель `translation-output.presets.ts`.

## Затронутые файлы

См. ссылки на находки выше (по файлам A5–A21 в исходном отчёте).

## Решение (по находкам)

1. **A5:** добавить `zod` в `dependencies` core и adapter-ai; включить проверку phantom-deps (knip/depcheck).
2. **A9/A10:** вынести реализацию из index в `generate.ts`/`rate-limit.service.ts`; единый `withInstrumentedCall(requestKind, model, options, fn)`.
3. **A11:** один тип `GenerateObjectFn = AIPort["generateObject"]`, все модули импортируют его.
4. **A15:** промпт+схему уведомлений вынести в core-модуль; имена языков из language-registry.
5. **A16:** обязательные deps сделать обязательными; опциональность — раздельными фабриками.
6. **A17:** фабрика `createAIAdapter({ apiKey, metricSink, timeoutProvider })`; синглтонность — забота композиционного корня.
7. **A19:** единый экспортируемый union + реестр «тип → picker» (map-based) в scheduler.
8. **A20:** типизированный `t<K>()` с per-key параметрами; `I18nKey = keyof typeof en` через `resolveJsonModule`.
9. **A21:** оставить `getLogger/setLogger`; структурный тип схемы вместо `ZodSchema`; `channelHint` вместо «Telegram»; удалить шим и deprecated-алиасы.

## Критерии приёмки

- [ ] `pnpm lint:knip` не показывает фантомных зависимостей.
- [ ] Index-файлы содержат только re-export (Hard Rule #4).
- [ ] `GenerateObjectFn` — один тип; костыль TS2308 убран.
- [ ] Новый тип уведомления добавляется регистрацией, не правкой switch.

## Тесты (spec-first)

- Каждая правка — со своим целевым тестом (map-based picker, типизированный `t()`, фабрика адаптера).
- Регрессия сборки/линтов после каждого слайса.
