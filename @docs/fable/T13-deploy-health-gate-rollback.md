# T13 — Health-гейт деплоя + откат + expand/contract миграции

- **Приоритет:** P0 (деплой без страховки = мгновенный прод-инцидент)
- **Фаза:** 2 — Устойчивость и наблюдаемость
- **Оценка:** ~2 дня
- **Зависит от:** [T12](T12-readiness-and-alerts.md) (readiness-эндпоинт)
- **Блокирует:** —
- **Связано:** [T26](T26-migration-hygiene.md)
- **Находки:** C5, F2

## Проблема

`.github/workflows/deploy.yml:166-178` — порядок `migrate` → seed → `up -d`. Между миграцией и переключением контейнеров старый бот работает против новой схемы (деструктивная миграция = мгновенный инцидент). После `up -d` нет проверки, что контейнеры стали healthy (crash-loop → workflow всё равно зелёный). `docker image prune -af` удаляет предыдущие образы — быстрый откат невозможен.

## Затронутые файлы

- `.github/workflows/deploy.yml:166-178`.
- `deploy/docker-compose.yml` — healthcheckّي (координация с [T12](T12-readiness-and-alerts.md)).

## Решение

1. **Health-гейт:** после `up -d` — цикл ожидания `docker inspect --format '{{.State.Health.Status}}'` (на базе `/readyz` из [T12](T12-readiness-and-alerts.md)); при не-healthy — fail workflow.
2. **Откат:** хранить тег предыдущего релиза (файл `PREVIOUS_RELEASE` на VPS); не делать `prune -af` сразу — оставлять предыдущий образ; документированная процедура rollback.
3. **Expand/contract для миграций:** деструктивные изменения схемы разбивать на обратно-совместимые шаги (expand → deploy кода → contract), чтобы старый и новый код работали с промежуточной схемой.

## Критерии приёмки

- [ ] Crash-loop после деплоя → workflow падает (не зелёный).
- [ ] Предыдущий образ доступен для отката; процедура описана в `@docs/`.
- [ ] Гайдлайн expand/contract зафиксирован; деструктивные миграции проходят ревью на совместимость.

## Тесты (spec-first)

- Прогон деплоя с заведомо ломающимся контейнером → workflow fail (можно на staging).
- Проверка, что предыдущий образ остаётся после успешного деплоя.

## Примечания

`db:migrate` применяется только в CI на merge в master (CLAUDE.md Hard Rule #3) — expand/contract касается именно этого шага. Координация с уборкой миграций [T26](T26-migration-hygiene.md).
