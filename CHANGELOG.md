# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- **Unrecognized-word guard** (Task 70) — stops the bot fabricating a confident card for a word that does not exist. Motivated by the "stroha" incident (a diacritic-stripped typo for Czech "strohá") where a preflight false-"proceed" led to a fully invented dictionary card. As defense-in-depth behind the preflight, the **main translation call** now also assesses whether the source headword is a real, correctly-spelled word/expression in the source language (new metadata fields `sourceWordRecognized` / `suggestedCorrection` — no extra AI call; word/phrase inputs only, opt-in via `assessSourceExistence`, off for batch/topic/video flows). An unrecognized headword yields a distinct **"unrecognized word"** clarification (reason `unrecognized_word`) offering any confident correction as a button plus "➡️ Translate as written" (reuses the Task 69 confirmation UI). Only after the user overrides is the word translated as written — the card then carries a caveat line ("⚠️ Not found in standard dictionaries — translated literally") and the saved entry is flagged **`unverified`** (new column on `vocabulary_entries`, migration `0041`). Unverified entries are **excluded from daily notifications and SRS word suggestions** (the notification dictionary picker now skips them). New telemetry counter `bot_unrecognized_word_total{outcome}` (`correction_offered` / `translated_as_written` / `rejected`). New i18n keys `translationClarifyReasonUnrecognized`, `translationTranslateAsWritten`, `translationAsWrittenCaveat`, `translationNoMoreMeanings` in all 11 locales. The dead no-op language validator (a leftover after franc-min was removed) was deleted so the validation stage honestly reflects what it checks. Additionally, the **"Other meaning"** button no longer surfaces a scary error when the pipeline has nothing new to offer (or fails) — it restores the card and shows "ℹ️ No other meanings available." instead. See `@docs/tasks/70-unrecognized-word-guard.md`.
- **Input typo & error detection in translate mode** (Task 69). The existing AI preflight now also catches typos and broken input — no extra AI call, no local spell-checker. A minor, unambiguous typo is fixed silently (new preflight outcome `proceed_with_correction`): the pipeline translates the corrected text and the reply is annotated with "✏️ Fixed: *original* → *corrected* — {why}" (the corrected form is what gets saved to the dictionary, so no typo cards enter SRS). Severe or ambiguous typos still use `confirm_typo_suggestion` with "✅ Yes, I meant …" / "➡️ Translate as written" buttons — choosing "translate as written" re-runs verbatim (saving the exact input) and never re-asks. Broken sentences are translated as their reconstructed meaning with the corrected sentence and a short error note; a confirm dialog appears only when the meaning cannot be reconstructed. The severity boundary and the correction/error `explanation` (now written in the user's `nativeLang`, length-capped) live in the preflight prompt. Language-clarification keyboards now render **flag + code** buttons (e.g. `🇬🇧 EN`) built on our side from `langCode` in rows of up to 4, with the "Add context" button on its own row and a hint line explaining the icons — model option labels no longer carry language names. New telemetry counter `bot_input_correction_total{outcome, input_type}` (`auto_corrected` / `confirm_shown` / `confirmed` / `translate_as_written`). After the language/mistype confirmation flow the preflight runs with a no-correction flag (`skipInputCorrection`) so the same word is never re-questioned. **The typo check is not gated on language detection**: confident detection does not mean correct spelling ("stroha" was confidently detected as Czech and translated verbatim although only "strohá" exists). The context-enrichment layer now reports whether the input exists in the source-language dictionary (`dictionaryHit`), and a dictionary miss forces the AI preflight to run even at high detection confidence — for every language; the preflight prompt carries the dictionary-miss signal plus an explicit rule that missing/wrong diacritics (stroha → strohá, uber → über, cancion → canción) are minor typos to restore. Sentences (never dictionary-checkable) now always get the preflight error check in translate mode. New i18n keys `correctionNotice`, `sentenceErrorNotice`, `translationClarifyLanguageHint` in all 11 locales. See `@docs/tasks/69-input-typo-validation.md`.
- Bot latency observability in Prometheus/Grafana, closing the blind spot found while investigating the 2026-07-02 delayed-answer report. New `update-metrics` middleware (registered before session middleware) records `bot_update_handling_duration_seconds{update_type}` for every update, `bot_update_delivery_lag_seconds` from the Telegram message timestamp (long-polling delivery delay), and logs a `Slow update handling` warning to Loki when handling or delivery exceeds 3 s. Postgres-backed session storage now records `bot_session_storage_duration_seconds{op=read|write|delete}` — a direct view of Neon round-trip latency (including autosuspend wake-ups) on every update. Three new P95/P50 panels on the Grafana **Polyglot Bot** dashboard: Update Handling Duration, Update Delivery Lag, Session Storage / Neon Latency.
- Persistent loading feedback for long bot operations. On-demand card sections that previously ran with **no waiting UX and swallowed errors silently** — "Other meaning", grammar breakdown, etymology, per-language grammar detail — now swap the card's buttons for an inert "⏳ Loading…" button while generating (the callback is answered only at the end, so Telegram's button spinner also stays visible), restore the card and show an explanatory alert on failure. Notification reveal/learned callbacks get the same loading button (their user-language and entry lookups now run in parallel, saving one Neon round-trip). Translate and mentor text flows show a "typing…" chat action during the silent pre-phase before their loader message appears. New i18n keys `loading` and `loadingTimeout` across all 11 locales.
- **Real cancellation of hung AI requests** at the adapter boundary (`packages/adapters/ai/src/index.ts`). Every `generateObject` / `generateText` / `generateChat` call now runs under an `AbortController` whose signal is passed to the Vercel AI SDK, so a single wall-clock budget bounds the whole call **including the SDK's internal retries**. When the budget elapses the in-flight HTTP request is genuinely aborted — freeing the socket and the OpenRouter concurrency slot instead of leaving it hanging in the background — and the adapter throws a typed `AITimeoutError` (`@polyglot/core`), logged as a failed request. This closes the gap left by the bot's `withTimeout` guard, which only abandoned the `await` (its own doc: "the underlying work is not cancelled"). The budget is **admin-managed** — a new `requestTimeoutMs` field on the AI Defaults settings (stored in the DB `system_settings` `ai.defaults` row, editable in the admin panel's **AI Defaults** tab, `1000–20000 ms`, default **15 s**). The adapter reads it through an injected provider (`setAIRequestTimeoutProvider`, wired at the bot composition root over the cached `SettingsService` — same dependency-injection pattern as the metric sink), so changing it in the admin panel takes effect without a redeploy, and it falls back to 15 s if unset/invalid. It is deliberately kept below the bot's 20 s loader guard so the adapter cancels first and the user still sees the friendly "taking longer" fallback. A new `isUserFacingTimeout` predicate (`apps/bot/src/utils/long-op.ts`) maps both `AITimeoutError` and the op-level `OperationTimeoutError` to the "⌛ This is taking longer than expected. Please try again." message across every long-op catch site (translate, alt-meaning, grammar detail, mentor, dictionary, notification callbacks). Directly addresses the 2026-07-01 freeze, where a rate-limited `:free` model's un-aborted retries held resources for 40–110 s.
- Timeout guard (20 s, `withTimeout` in `apps/bot/src/utils/long-op.ts`) around every user-facing long operation (translation, alt-meaning, grammar, etymology, grammar detail, mentor chat, dictionary-entry translation, notification callbacks): instead of an endless loader, the user gets "⌛ This is taking longer than expected. Please try again." — motivated by the 2026-07-01 incident where free-tier model retries ran 40–110 s.

### Changed

- Bot update processing is now concurrent: replaced `bot.start()` long polling with `@grammyjs/runner` plus `sequentialize` keyed by chat id. One slow handler (AI call, cold Neon query) no longer blocks every other user's updates; each user's own updates still process in order, so the Postgres-backed session cannot race.

- Wired the official **Grafana MCP server** (`grafana/mcp-grafana`, Docker image `mcp/grafana`, stdio transport) into Claude Code via a project-scoped `.mcp.json`. Lets Claude Code on a local machine read server logs (Loki/LogQL), metrics (Prometheus/PromQL), dashboards, and alert/scrape-target status **through the public Grafana** (`grafana.polyglot.monster`, TLS + auth) using a single read-only **Viewer** service-account token — Loki (`:3100`) and Prometheus (`:9090`) stay localhost-only on the VPS. The token is referenced as `${GRAFANA_SERVICE_ACCOUNT_TOKEN}` (kept in the local environment, never committed); `.env.example` documents the variable. Setup, token creation, and usage examples in `@docs/observability-mcp.md`. No application source code changed — config/docs only.
- Landing page (`apps/landing`): added a **Supported languages** section listing all 11 fully supported languages with flags and native names (English, Russian, Czech, German, French, Spanish, Italian, Portuguese, Ukrainian, Polish, Kazakh), and a new **"Powered by AI"** section explaining how the bot customizes each card and the whole learning flow to the user's level, goals, and languages. Hero copy now leads with the AI personalization angle. The Features grid is now a fixed responsive 3-per-row layout (1/2/3 columns). Improved crawler/SEO discoverability: `robots.txt`, `sitemap.xml`, canonical link, `SoftwareApplication` JSON-LD structured data (with `inLanguage` for all 11 languages), and Twitter/OG card metadata — all content is statically rendered into HTML by Astro.
- Translated the bot interface into **all supported languages** and added **Kazakh** (`kk`) as a new interface language. Previously only `en`, `ru`, and `cs` had locale files (the remaining languages silently fell back to English); now `de`, `fr`, `es`, `it`, `pt`, `uk`, `pl`, and `kk` each ship a complete locale file covering every i18n key. Added `"kk"` to `SupportedLang`, registered all locale files in the i18n loader, seeded Kazakh into the `languages` table (`is_supported = true`, migration `0040_add_kazakh_language`) so it appears in the language picker, and added it to the test language registry. A new data-driven test suite enforces locale completeness — every locale must have the same key set as `en.json`, no empty values, and identical `{placeholder}` tokens.
- Added per-language **translation traits** held in code (`packages/core/src/modules/translation/language-traits.ts`): a compact, language-specific directive (e.g. Russian aspect pairs, German lemma articles, Kazakh vowel-harmony/Cyrillic, Ukrainian russism avoidance, `pt`/`es` variant prompts) is now injected into the per-language translation prompt. Because the service builds one prompt per target language, only the requested language's directive is added (~1 line), keeping the prompt within lite-model token budgets. New `LANGUAGE_TRAITS` map + `buildLanguageTraitsHint` consumed by `buildTranslationPrompt`.
- Added on-demand **Etymology** (`🔍 Этимология`) to translation cards: tapping the button generates a concise 2–4 sentence etymology of the original term, written in the user's native language, explaining where it comes from and how it acquired its meaning. Shown for single words and short phrases when the source term is in a learning language (`sourceLang !== nativeLang`) — hidden for sentences and native-language input. The button sits next to the grammar button and disappears once its section is added; the result is cached per card and cleared on "Другое значение" regeneration. Gated behind a new `etymology` feature key (via `FeatureAccessPort`) for future premium integration. New `generateEtymology` core service and i18n keys (`etymology`, `etymologySection`, `etymologyLocked`) in en/ru/cs.

### Changed

- Video vocabulary extraction now **skips words the learner already has**, so processing more videos stops re-surfacing the same phrases. Before the AI call, the pipeline gathers the user's known phrases in the video's language — the `original` of every active saved-dictionary entry (`vocabularyRepository.findOriginalsByUserAndSource`) plus every phrase generated in their previous videos of that language (`videoVocabularyRepository.findKnownPhrasesByUser`, excluding the current process) — and feeds them to `extractPhrasesFromTranscript`. They are applied two ways: as a soft "## Already Known — DO NOT extract these" hint in the prompt (de-duplicated case-insensitively, capped at 500 items so a large vocabulary can't blow the token budget) and as a **hard post-filter** that drops any returned phrase whose normalized (trim + lowercase) form matches a known one — so duplicates never reach the DB even if the model ignores the hint. New shared `normalizePhrase` helper. Backward-compatible: `knownPhrases` defaults to empty, preserving previous behavior when nothing is known.
- Video vocabulary now extracts **far more phrases per video, scaled to video length**. The per-video phrase target is computed from the transcript duration (`computePhraseTarget`: ~20 phrases at 30 min, ~30 at 1 h, ~40 at 2 h, +10 per doubling) and clamped to an admin-configurable `[minPhrases, maxPhrases]` range (defaults 15/40). The extraction prompt was rewritten to **aim for the full target** instead of "quality over quantity" (which made the lite model return only a handful), and the AI output-token cap — previously hard-coded at 4096 and silently truncating long results — is now sized to the target (`maxTokens` plumbed through `GenerateOptions`). `VideoVocabularyConfig.maxPhrasesDefault` was replaced by `minPhrases`/`maxPhrases`, now editable in a new **Video Vocabulary** tab in the admin Settings panel (new `/api/settings/video-vocabulary` admin-api route). The extraction model continues to come from DB config (`extractionModelId`, also editable in that tab).
- Settings → learning languages now asks for a **CEFR level when adding a language**. Tapping a new language opens an A1–C2 picker and the language is saved together with its level only once the level is confirmed (mirrors onboarding, feeding the per-language level used for video phrase selection). Tapping an already-selected language removes it immediately. Removed the redundant **Done** button — each choice auto-saves, and the existing **Back** exits the picker.
- Monitoring stack (`deploy/monitoring/docker-compose.monitoring.yml`): raised container memory limits that were running hot — `cadvisor` 128m → 512m (still ~94% at 256m) and `grafana` 256m → 384m (was at ~84%) — to give both headroom and avoid OOM pressure.
- Translation card keyboard: moved the **Save** button to the bottom row (below the learning-aid buttons) and renamed **Clarify** → **Clarify meaning** (`🎯 Уточнить значение` / `🎯 Upřesnit význam`) for clarity.
- Notifications: users can now configure **multiple notification times per day** (up to 12) instead of a single time. The `/settings → notifications → choose times` picker became a multi-select 30-min grid (✅ on selected slots), and the sub-menu shows the full list of times. Replaced the single `notificationTime` column with a `notificationTimes` text array (existing times preserved via backfill). De-dup for dictionary (`srs`) notifications now avoids any word sent in the last 24h (was: last 3 words), so high-frequency users don't see same-day repeats. The enable/disable toggle stays separate, so pausing keeps configured times. Limit is configurable via `NotificationDefaults.notificationTimesLimit` (default 12). See `@docs/tasks/68-multiple-daily-notifications.md`.

- Parallelized AI translation calls: split single heavy multi-language generation into N+1 concurrent calls (1 metadata + 1 per target language), reducing translation latency from ~5s to ~1.5s.
- Added universal language-specific directive to translation prompt: AI now includes grammatically essential markers (articles, gender, verb aspect) appropriate for each target language.

### Security

- **Redact PII from logs shipped to third parties** (Fable T10, finding S7). The core pino logger had no `redact` config, so user message fragments and identifiers reached Betterstack/Loki at `info`+ — including a mentor-chat **error** log that shipped a 50-char slice of the user's message. Configured pino `redact` for the PII/secret paths `text`, `username`, and `password` (top-level and one level nested) → `[Redacted]`. The mentor error now logs `textLength` (a length category) instead of raw text; the two debug-only routing logs use `textPreview` (visible for local debugging, never shipped because prod runs at `info`); and the bot-startup log's own handle was renamed `username` → `botUsername` so it stays visible (it is not user PII). Identifiers like `userId`/`telegramId` are kept for diagnostics. (Email in the T05 failed-login log is intentionally not redacted — it is needed for brute-force alerting.)
- **Closed the anonymous leak of internal reports** (Fable T09, finding S3). `apps/admin/public/reports/` — the full database schema, architecture map, observability report, and the ~1950-scenario test catalog (file paths + behavior descriptions) — was served by Astro as **unauthenticated static assets** and proxied to the internet, handing any anonymous visitor a complete map of the system. The reports directory was moved out of `public/` to `apps/admin/reports-data/` (so it is no longer statically served) and is now delivered by a new **cookie-gated SSR endpoint** (`src/pages/reports/[...file]`) plus auth middleware: `/reports/*` requires a valid `admin_token`, verified against admin-api `/api/auth/me` (fail-closed), so an anonymous `GET /reports/database-schema.html` now returns **401**. The admin login stores its JWT in a same-origin cookie (alongside localStorage) so the panel's report iframes and `test-catalog.json` fetch keep working for authenticated admins. The report-generating scripts (`test-catalog.mjs`, `sync-admin-reports.mjs`), the admin Dockerfile (`REPORTS_DIR`, ships the dir), the compose admin service (`ADMIN_API_INTERNAL_URL`), and the CLAUDE.md quality-gate path were updated to the new location. A second nginx-level perimeter control is tracked under T20.

### Added

- **Rate limiting on the admin API, with a hard anti-bruteforce limit on `/api/auth/login`** (Fable T05, finding S2). The login endpoint is publicly reachable through nginx and previously had no attempt limit, delay, or lockout — only bcrypt slowed a password-guessing attack. Registered `@fastify/rate-limit`: a soft global limit (200 req/min per client IP) plus a tight per-route limit of **5 login attempts/min per IP** on `/api/auth/login` (returns HTTP 429 when exceeded; a legitimate login within the limit is unaffected). Enabled Fastify `trustProxy` so the limit keys on the real client IP (`X-Forwarded-For`) rather than the nginx address. Failed login attempts are now logged (email + IP, **never the password**) for future brute-force alerting. A second nginx-level `limit_req` layer is tracked under T20. (The single "Invalid credentials" response — no user enumeration — is preserved; JWT revocation is T06.)

### Fixed

- **Re-saving a word you previously deleted no longer crashes** (Fable T04, findings C2/E1). Deleting a word from a notification is a soft-delete (the row stays with `is_active = false`), but the duplicate check (`findByOriginalAndSource`) only looks at active rows, so a re-save found nothing and inserted — colliding with the `(user_id, original, source_lang_id)` unique index and throwing an unhandled `23505`. `vocabularyRepository.create` now **reactivates** the existing row via a race-safe `ON CONFLICT DO UPDATE` (on the entry's unique key and each translation's `(entry_id, target_lang_id)` key): the entry and its translations are flipped back to active with the freshly-saved content, while the translations' **SRS columns are left untouched** so review history survives a delete + re-save. No check-then-insert window (complements T18), and no schema/migration change — the fix reuses the existing unique index as the conflict target. (Case-insensitive de-duplication of `Hello` vs `hello` is tracked separately under T18/E9.)
- **Removed the composition-root `as unknown as ServiceContainer` cast and aligned `estimateCost` with its port** (Fable T03, finding C3). The double cast at the bot's composition root disabled all type-checking between adapter implementations and their port contracts, which was actively hiding a real bug: the AI port declared `estimateCost(inputTokens, outputTokens, modelId)` but the adapter implemented `estimateCost(tokens, model)`, so a call through the port passed the output-token **count** where the **model id** was expected → `findModel` returned undefined → the default price was charged silently. The adapter's `estimateCost` now matches the port signature and delegates to the existing correct `calculateCost`. Removing the cast (`const container: ServiceContainer = { … }`) surfaced several other silent port/adapter drifts, now fixed by widening the port return types to the truth the adapters already return: `UserRepository.updateNativeLang` / `updateLearningLangs` / `updateInterfaceLang` / `updateActiveMode` / `updateNotificationPrefs` (→ `Promise<UserLanguageSettings | null>`), `markOnboarded` (→ `Promise<User>`), and `VocabularyRepository.updateTranslation` (→ `Promise<VocabularyTranslation>`). The container is now compiler-verified to satisfy every port, so future drift fails the build instead of being masked.
- **Hardened the out-of-set "add & translate" flow** (Fable T02, finding B9) — closing three defects in the committed out-of-set diff. (1) **Localization:** the callback's "session expired" and "maximum languages" alerts were hardcoded English despite the flow otherwise being fully localized; they now resolve through `t()` (new `staleSession` key added to all 11 locales; the limit alert reuses `maxLangsReached`). (2) **Error separation:** *any* failure of `updateLearningLangs` (including a DB outage) was reported to the user as "you've reached the maximum number of languages". The language limit is now checked explicitly **before** the write (showing `maxLangsReached` without touching the DB), and a genuine write failure surfaces the generic `translationError` instead — a DB fault is no longer masked as a limit. (3) **Single-slot race:** `pendingOutOfSet` held one word in a single session slot, so two consecutive out-of-set prompts (e.g. a Spanish word then a Portuguese one) could add the language from the tapped button but translate the *other* word. It is now a map keyed by the prompt's Telegram message id (mirroring `translationMap`), so each button carries its own word; a used or drifted button resolves only to its own entry and its keyboard is retired (`editMessageReplyMarkup`) after selection. Also registered the `tr:oos` prefix in the `callbacks/contracts.ts` restart-safety registry (session-backed, keyed by message id).
- **Mentor mode no longer loses its history on every reply, and a single bad field no longer wipes the whole bot session** (Fable T01, findings C1/B1). The session validator's `VALID_MODES` set omitted `"mentor"` while `UserMode` declared it, so after `/mentor` each subsequent update failed `isValidSessionData` → "Resetting corrupt bot session" → the entire session (mentor history, `translationMap`, all pending state) was deleted; routing only survived because auth middleware re-hydrated the mode from the DB. Fixed at the root by introducing a single source-of-truth `USER_MODES` array in `apps/bot/src/types.ts` from which both the `UserMode` union **and** every runtime `VALID_MODES` set (session-storage and the previously-drifting copy in `middlewares/auth.ts`) are now derived — a mode can no longer be added to the type without being accepted by validation (enforced by an exhaustiveness test over `USER_MODES`). Session reads are now **non-destructive**: an invalid/unknown `activeMode` is repaired in place (defaulted, and the repair persisted) while `translationMap`, mentor history and pending state are preserved; a full delete happens only for genuinely unrecoverable (non-object) payloads. (Fable T01.)
- **Out-of-set languages are now consistently offered "add and translate" instead of slipping through** (Phase 1 of the language-guard fix). Investigating a 2026-07-03 report — the bot correctly blocked Spanish ("add this language") but silently translated Kazakh `Керемет мырзалар` and Slovak `Prečo` — surfaced that the out-of-set block was bypassable: the AI clarification could offer a **not-studied language as a tappable source** (`tr:clarify:option:` / `tr:clarify:lang:`) and translate it with no check that the language was in the user's set (`resolveTargetsForClarifiedSource`). Both the main detection guard and the clarify-callback source-selection now route a supported-but-not-studied source through a single **add-and-translate** prompt (`showAddLanguagePrompt`): `[➕ Add <lang> & translate]` / `[➡️ Translate once]` / `[Cancel]` (`tr:oos:*` callbacks). "Add" appends the language to the learning set (`userRepository.updateLearningLangs`) and translates; "once" translates without persisting. Gating uses the new `isSupportedLanguage()` registry predicate (the 46-language study registry) — **not** the i18n `isSupported` (11 UI locales) — so an unsupported detected language still gets the plain informational block (it can't be added). New i18n keys `outOfSetPrompt`, `outOfSetAddButton`, `outOfSetTranslateOnce` across all 11 locales. Also added a **word-count-independent alphabet-exclusion signal** (`detectOutOfSetByAlphabet`): when the input carries letters that no studied-language alphabet can produce and exactly one supported language can (ñ→es, ß→de, ğ→tr, ә→kk), it flags that language on the first pass — before, this was only caught for single Latin words via the dictionary sweep or for 3+ words via franc, so a confident mis-coercion slipped through. It is conservative (a diacritic shared by several languages never fires, protecting loanwords like "naïve"/"café"). (Follow-ups: multi-word/Cyrillic dictionary sweep for same-alphabet cases like `Керемет мырзалар`/`Казакша`, and restricting the AI clarification to in-set source options.)
- Language detection no longer misidentifies single foreign words as the user's sole Latin-script language (e.g. Czech "Strohá" was detected as English for a ru+en user, because being the only Latin candidate granted 0.9 confidence to any Latin text). Detection now follows lingua-style negative evidence: per-language alphabets (`packages/core/src/modules/language-detect/alphabets.ts`) veto candidates whose alphabet can't produce the input ("á" rules out English), the 0.9 "unique script candidate" score is kept only for near-1:1 scripts (hangul/kana/greek/devanagari/arabic/CJK) or when the alphabet check passes, and alphabet exclusion also narrows shared-script candidate sets ("привіт" now resolves to Ukrainian since "і" excludes Russian). Shared diacritics (á, é) now score 0.4 instead of a decisive 0.8 — only globally unique marks (ř→cs, ł→pl, ß→de) stay strong. A new **dictionary sweep** (`createWordLanguageSweep` over `word_context` across all supported languages) verifies heuristic-only single-word detections and detects out-of-set languages for single words — the existing `detectOutOfSetLanguage` only covered ≥3-word input — replying "🚫 {language} isn't in your selected languages" instead of mistranslating. The AI fallback may now answer with a language outside the candidate set (`AIStrategy.detectOpen`), feeding the same out-of-set reply. New telemetry events `detected`/`out_of_set` in `language_detection_events` build a golden regression set from real traffic.
- Language detection no longer silently mistranslates input written in a language the user hasn't selected. Detection is a closed-set classifier (it only returns one of the user's configured languages), so e.g. a German phrase from a user with ru/en/cs/kk was coerced to the nearest candidate (English) and translated wrongly. Added a conservative out-of-set check (`detectOutOfSetLanguage`, unconstrained `francAll` over ≥3-word input) that detects the real language and replies "🚫 {language} isn't in your selected languages" instead of translating. Also fixed two Kazakh detection gaps: `kk` was missing from `ISO1_TO_ISO3` (franc could never see Kazakh) and from the Cyrillic script list (Cyrillic Kazakh never resolved by script). New i18n key `languageNotSelected` across all locales.
- Localized all remaining hardcoded English strings in the video vocabulary feature: callback toasts ("Phrase not found", "Already saved", "Language not found"), duration fallback ("Unknown"), phrase type labels ("[word]"/"[phrase]"), and page indicators. Added 10 new i18n keys (`videoPhraseNotFound`, `videoAlreadySaved`, `videoLanguageNotFound`, `videoDurationUnknown`, `videoTypeWord`, `videoTypePhrase`, `videoPage`, `videoSavedToast`, `videoProcessingCancelled`, `videoPhrasesExtracted`) with translations for all three locales (en, ru, cs).
