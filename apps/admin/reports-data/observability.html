Polyglot Observability

Метрики, логи и дашборды — как устроен мониторинг Telegram-бота Polyglot

Обзор

Стек обсервабилити Polyglot построен на четырёх основных компонентах: сбор метрик (Prometheus), агрегация логов (Loki + Promtail) и визуализация (Grafana). Дополнительно используются Node Exporter и cAdvisor для системных и контейнерных метрик.

Все компоненты запускаются через docker-compose.monitoring.yml и используют официальные Docker-образы — собирать собственные образы не нужно. Конфигурация монтируется через volumes.

Инструменты

🔥

Prometheus Метрики

prom/prometheus:latest · :9090

Time-series база данных для метрик. Каждые 15 секунд опрашивает (scrape) все настроенные цели и сохраняет значения.

  • Собирает метрики бота (bot:9090/metrics)
  • Собирает метрики хоста через Node Exporter
  • Собирает метрики контейнеров через cAdvisor
  • Мониторит самого себя
  • Хранение: 14 дней, TSDB
📊

Grafana Визуализация

grafana/grafana:latest · :3000

Центральный UI для визуализации всех данных. Подключается к Prometheus и Loki как источникам данных.

  • 4 преднастроенных дашборда (auto-provisioned)
  • Datasource: Prometheus (метрики по умолчанию)
  • Datasource: Loki (логи)
  • Регистрация пользователей отключена
  • Доступна по адресу grafana.polyglot.monster
📜

Loki Логи

grafana/loki:latest · :3100

Система агрегации логов от Grafana Labs. Принимает логи от Promtail, индексирует по лейблам и хранит на файловой системе.

  • Хранение: файловая система (TSDB-индекс)
  • Схема: v13, период индекса 24 часа
  • Retention: 14 дней (336 часов)
  • Компактификация каждые 10 минут
📨

Promtail Логи

grafana/promtail:latest · :9080

Агент-коллектор логов. Автоматически обнаруживает Docker-контейнеры через Docker socket и отправляет их логи в Loki.

  • Auto-discovery контейнеров (refresh: 5 сек)
  • Парсит JSON-формат Docker-логов
  • Извлекает поле level из JSON
  • Добавляет лейблы: container_name, stream
🖥️

Node Exporter Система

prom/node-exporter:latest · :9100

Экспортёр системных метрик хоста. Предоставляет данные о CPU, RAM, диске, сети и других параметрах ОС в формате Prometheus.

  • CPU usage, load average
  • Memory & swap usage
  • Disk I/O и свободное место
  • Network traffic (bytes in/out)
📦

cAdvisor Система

gcr.io/cadvisor/cadvisor:latest · :8080

Container Advisor от Google. Собирает метрики производительности для каждого Docker-контейнера и экспортирует в формате Prometheus.

  • CPU и memory usage per container
  • Network traffic per container
  • Disk I/O per container
  • Контейнерные лимиты и throttling
🎯

prom-client Метрики

npm: prom-client ^15.1.3 · apps/bot/src/metrics.ts

Node.js-библиотека для создания Prometheus-метрик внутри приложения. Определяет кастомные счётчики и гистограммы бота.

  • HTTP-сервер на порту 9090 (/metrics, /healthz)
  • Автоматический сбор Node.js-метрик (CPU, memory, event loop, GC)
  • Кастомные метрики бота (см. ниже)
🌲

Pino Логи

packages/core/src/logger.ts

Быстрый JSON-логгер для Node.js. Весь вывод идёт в stdout в формате JSON, откуда Docker и Promtail забирают логи.

  • Уровень по умолчанию: info
  • Структурированный вывод: logger.info(obj, msg)
  • Обязательные события: AI-запросы, ошибки валидации, нотификации, ошибки бота

Метрики приложения

Бот экспортирует следующие кастомные метрики через prom-client:

Метрика Тип Labels Описание
bot_translations_total Counter status Всего запросов на перевод
bot_translation_duration_seconds Histogram — Время выполнения перевода (buckets: 0.5, 1, 2, 5, 10, 30 сек)
bot_mentor_requests_total Counter status Всего запросов к менторскому чату
bot_mentor_duration_seconds Histogram — Время ответа ментора
bot_ai_requests_total Counter model, status Запросы к AI-провайдерам
bot_ai_tokens_total Counter model, type Потреблённые токены (input / output)
bot_telegram_messages_total Counter type Входящие Telegram-сообщения (callback / message / other)
bot_notifications_total Counter status Отправленные нотификации
bot_active_users_total Counter — Общее количество уникальных пользователей

Поток метрик

Путь метрики от приложения до графика в Grafana:

Приложение prom-client регистрирует Counter / Histogram
→
HTTP /metrics Экспорт в текстовом формате Prometheus на порту 9090
→
Prometheus Scrape каждые 15 сек, хранение в TSDB (14 дней)
→
Grafana PromQL-запросы → графики и панели

Поток логов

Путь лога от приложения до панели в Grafana:

→
Docker json-file driver захватывает stdout/stderr
→
Promtail Обнаружение контейнеров, парсинг JSON, извлечение level
→
Loki Индексация по лейблам, хранение 14 дней
→
Grafana LogQL-запросы → фильтрация и просмотр

Деплой и ресурсы

Мониторинг деплоится автоматически через GitHub Actions (.github/workflows/deploy-monitoring.yml):

  1. Checkout кода
  2. SCP конфигов на VPS в /opt/monitoring
  3. Создание Docker-сети polyglot-network
  4. Установка пароля Grafana из GitHub Secrets
  5. Pull официальных образов
  6. Запуск стека через docker compose up -d
